# DatasetGuard

DatasetGuard helps ML engineers find possible image leakage across `train`, `validation`, and `test` before training. It detects byte-identical files, images with identical decoded pixels, and visually similar candidates using a configurable 256-bit difference hash. Every result is queued for human review; it never deletes, moves, or rewrites source images.

## Quick start

Python 3.11+; no GPU, account, network service, or paid infrastructure.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python datasetguard.py demo --output outputs/demo-report.json
python app.py                 # http://127.0.0.1:8770
```

Scan your own directory:

```text
dataset/
├── train/class_a/image.png
├── validation/class_a/image.jpg
└── test/class_a/image.webp
```

```bash
python datasetguard.py scan dataset --threshold 12 --output outputs/report.json
```

The browser accepts the same structure as a ZIP. It limits uploads to 50 MiB, uncompressed data to 100 MiB and 500 entries, prevents path traversal, extracts into an isolated temporary directory, then cleans it up. Supported inputs: PNG, JPEG, WebP and BMP. Decode failures are recorded rather than silently ignored.

## How it works

- SHA-256 of original bytes detects exact copied files.
- SHA-256 of decoded, EXIF-oriented RGB pixels plus dimensions detects lossless re-encodings with the same pixels.
- dHash-256 resizes grayscale to 17×16 and compares adjacent pixels. Candidate distance is hash Hamming distance; lower means more similar.

Only cross-split pairs are compared. Priority is `exact_file`, then `exact_pixels`, then `near`. The default near threshold is 12 of 256 bits, configurable from 0–64. JSON contains paths, hashes, dimensions, distance, kind and `pending` review state. The UI lets a person mark `confirmed_duplicate` or `false_positive`, then exports a new manifest. It performs zero destructive actions.

Pair comparison is quadratic in image count. This clear MVP suits small datasets; production scale needs hash indexing/bucketing and streaming reports.

## Honest evaluation

The deterministic synthetic fixture has eight generated training scenes. Held-out splits contain one exact PNG copy, one resized/JPEG copy, one JPEG-reencoded copy, and five independently generated unrelated images. `demo` writes images plus ground truth, scans them, and reports pair-level precision/recall. Fixtures are original synthetic data released under CC0-1.0. No external dataset is bundled. See the committed [evaluation report](reports/synthetic-evaluation.json).

This small, simple fixture tests known transforms and false positives. dHash is sensitive to rotation/cropping, can miss semantic duplicates, and may flag unrelated low-detail images. It does not detect shared subjects, adjacent video frames, annotations, or metadata leakage. Output is a review aid—not proof of leakage or an instruction to remove data.

Credible project-specific validation requires a labelled sample from the target dataset, realistic augmentations and unrelated lookalikes, threshold tuning on a separate validation subset, then precision/recall on untouched test pairs.

## Tests and architecture

```bash
python -m pytest -q
```

`datasetguard.py` contains hashing, scanning, manifests, sample generation and CLI. `app.py` provides the local ZIP workflow. Tests cover known transforms, threshold effects, decoded-pixel equality, corrupt images, split validation, review validation, ZIP traversal and invalid layouts. CI reruns tests and the demo.

## Interview explanation

“I built a non-destructive image leakage auditor that distinguishes exact bytes, exact decoded pixels, and perceptual similarity. I designed explicit human review because a perceptual-hash candidate is not automatically a duplicate. I measured pair-level precision and recall on labelled synthetic transformations, tested archive security and failure cases, and documented where dHash stops being reliable.”
